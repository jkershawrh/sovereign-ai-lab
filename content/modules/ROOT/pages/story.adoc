= Demo Story & Message
:navtitle: Demo Story

*Time: ~5 minutes* +
*Role: Presenter, Lab Proctor, Executive Sponsor*

== Set The Stage

Most AI sovereignty conversations start too late. They ask where inference runs, but they do not ask who controls the model, who governs the data, what agents can touch, or whether anyone can prove what happened after the demo ends.

The audience should understand the opening problem before they see the stack:

* A model can run inside a region and still depend on opaque APIs.
* Data can stay local while tools, agents, or gateways move sensitive context somewhere else.
* A policy can exist on paper but still fail to control runtime behavior.
* An audit can describe intent without proving the actual sequence of events.

The lab sets up a stronger claim: sovereign AI requires evidence at every layer.

== Here Is The Story

Sovereign AI is not a location claim. It is an ownership, control, governance, and proof claim.

The lab should feel like a shift from "trust me" to "show me." Every major action creates evidence that can be inspected later: an attestation report, an AIBOM, a benchmark gate, a policy decision, a routing decision, or a ledger entry.

The short version is:

> Sovereign AI means you can possess it, run it, adapt it, govern it, and prove what happened.

Those five verbs are the story spine.

[cols="1,3,3",options="header"]
|===
|Verb |Audience question |Lab evidence

|Possess
|Do we control the model and artifacts?
|Open-weight Granite model references, model registry, AIBOM

|Run
|Does inference run on infrastructure we control?
|OpenShift/Oberon OVMS path, local vLLM simulation path

|Adapt
|Can we tune and evaluate the model for our jurisdiction?
|Ingest, synth, train, eval, benchmark thresholds

|Govern
|Can our rules control data, models, agents, and tools?
|OPA policies, semantic router, jurisdiction profiles, MCP gateway

|Prove
|Can we verify what happened after the fact?
|TDX attestation, promotion proof, ledger hash chain
|===

== Here Is How It Is Done

The demo is a proof walk through the stack. Each layer answers one trust question and produces one kind of evidence.

[cols="2,3,3",options="header"]
|===
|Layer |Trust question |Evidence

|Hardware trust
|Whose compute is this?
|TDX attestation report and ledger entry

|Platform
|Where is the workload running?
|OpenShift namespace, services, routes, and rollout status

|Models
|Whose model is this?
|AIBOM, base model license, training jurisdiction, benchmark gates

|Data governance
|Whose rules govern the data?
|OPA residency decisions and jurisdiction profiles

|Agent control
|Where does the prompt go?
|Semantic router classification and local routing decision

|Gateway and MCP
|What can agents touch?
|Jurisdiction-local tools and controlled gateway path

|Proof chain
|Can we prove it later?
|Ledger entries, chain verification, writer attribution
|===

== Presenter Arc

Use this arc for a 20-30 minute demo:

. *Set the stage:* A regional endpoint is not the same as sovereign control.
. *Tell the story:* Sovereignty means possess, run, adapt, govern, and prove.
. *Show the stack:* Each layer exists because it answers a trust question.
. *Walk the proof:* Show attestation, AIBOM, benchmark gates, routing, policy, and ledger verification.
. *Hand off to the lab:* Change jurisdiction and show that the same stack behaves differently under different governance rules.

== What To Say Out Loud

Use short framing language while moving through the lab:

* "Local is not enough. We need evidence."
* "This is not just a model call. It is a governed event."
* "The policy decision is useful now, but the proof is useful later."
* "The same stack can serve different jurisdictions because the rules are explicit."
* "Simulation mode is labeled. Production mode replaces simulated evidence with hardware-backed and independently reproducible evidence."

== What To Be Honest About

The lab is intentionally transparent about demo boundaries:

* TDX is real only on compatible hardware with attestation configured; otherwise it is simulated.
* Benchmark outputs are demo fixtures unless replaced by a real measurement harness and audited datasets.
* Local vLLM and OpenShift OVMS use different chat endpoints.
* Demo secrets and `latest` images are acceptable for a guided lab, not for production.
* Helm/RHDPS packaging remains the next phase.

== Success Criteria

By the end, the audience should be able to say:

* Sovereign AI means possess, run, adapt, govern, and prove.
* Every layer creates evidence.
* Policy is executable, not just documented.
* The ledger connects separate controls into one proof chain.
* The demo is honest about which evidence is real and which is simulated.
